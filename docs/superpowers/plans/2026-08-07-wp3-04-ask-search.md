# WP3-04 Ask and Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Redesign `/search` into query/results/preview and query/synthesis/references workspaces with cancellable streaming, addressable previews, and provenance that remains visible beside the answer.

**Status:** Complete and approved.

**Architecture:** Keep the existing Ask and Search APIs and hooks. Split the route monolith into two feature workspaces, add one URL-backed resource-preview hook, and use the ResearchWorkbench from WP3-03. Add AbortSignal support to the existing fetch path rather than another streaming client.

**Tech Stack:** Next.js search params, existing SSE proxy/fetch implementation, TanStack Query, ResearchWorkbench, MarkdownRenderer, Vitest.

## Global Constraints

- Preserve `?mode=ask|search&q=...` command-palette/deep-link behavior.
- Ask supports stream, cancel, error, retry, advanced model selection, copy, and save-to-notebook.
- Search supports text/vector modes, source/note scope, relevance, embedding dependency, and resource preview.
- References are numbered, typed, labeled, keyboard-operable, and open without discarding the answer.
- Missing/revoked references remain visible as unavailable.
- Vector search explains its embedding dependency and stays disabled when no embedding model exists.
- Query, active mode, options, selected result, preview, and completed answer survive responsive pane changes.
