# WP3-01B Deployment-Level White-Label Branding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make application identity configurable per deployment—name, logo, favicon, primary action color, and support URL—without code edits or image rebuilds, while preserving the approved semantic, provenance, focus, typography, and accessibility contract.

**Architecture:** Follow the single-tenant deployment decision in `docs/TENANCY.md`. A server-only loader reads one trusted JSON document from `BRAND_CONFIG_PATH`, validates it with the already-installed Zod package, merges safe defaults, and caches the result for the process lifetime. The root layout injects the public config through one React provider and CSS custom properties. No database model, request-time tenant lookup, upload UI, YAML parser, arbitrary CSS, or new dependency is introduced.

**Tech Stack:** Next.js 16 App Router, React context, TypeScript, existing Zod, CSS custom properties, Vitest, Testing Library.

## Global Constraints

- Branding is deployment-level and resolved once per application process, never per request or per user.
- The supported public contract is exactly `appName`, `logoUrl`, optional `logoDarkUrl`, optional `faviconUrl`, `actionLight`, `actionDark`, and optional `supportUrl`.
- Keep Source Sans 3 and Source Serif 4 fixed. Do not support configurable fonts, arbitrary CSS, general token overrides, secondary palettes, or an admin theme editor in WP3.
- Config may affect the primary action pair only. It cannot override selected, provenance, focus, success, info, warning, error, canvas, surface, or ink roles.
- Reject invalid JSON, unknown properties, unsafe URLs, and colors that cannot reach 4.5:1 with either the light or dark foreground candidate. Fail startup with a concise operator-facing error; never silently serve a partially invalid brand.
- `logoUrl`, `logoDarkUrl`, `faviconUrl`, and `supportUrl` accept only root-relative paths or `https:` URLs. Reject protocol-relative, `data:`, `javascript:`, and path-traversal values.
- Brand identity is not translated. Surrounding sentences remain localized and interpolate the configured `appName`.
- The repository default remains suitable for development. A commercial deployment must provide an approved client name and assets; this plan does not invent them.
