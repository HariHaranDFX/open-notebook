# WBS 4.20 — Entra ID group sync (design)

Date: 2026-09-20  ·  Status: Approved (design), Implementation branch `feat/wbs-4.20-entra-group-sync`

## Goal

Let a deployment admin **link** a Microsoft Entra security group into Open Notebook, and keep its membership continuously reflected in the local ACL so that changes made in Entra propagate without re-sharing every resource.

Acceptance (from [scripts/wbs_tasks.py:1297](../../../scripts/wbs_tasks.py)):
> Admin can link an Entra group; membership changes in Entra reflect in ACL without re-sharing.

## Non-goals (deferred)

- Webhooks / change notifications — subscription lifecycle out of scope.
- Transitive / nested-group expansion (Graph `transitiveMembers`).
- JIT-stub users for Entra members that never logged in — that is **WBS 4.21**.
- Any change to the ACL evaluator (`api/ownership.py`); grants against `user_group` where `source='entra'` already work today because "highest role wins across direct + group grants" is unchanged.
- Any change to how local groups behave.

## Constraints and existing invariants (do not violate)

- Tenancy stays Model A — grants never cross deployments ([TENANCY.md](../../TENANCY.md)).
- No new Python dependency (ponytail — `httpx` and `asyncio` cover it).
- No new schema — [migration 28](../../../open_notebook/database/migrations/28.surrealql) already reserves `user_group.source` and `user_group.entra_group_oid` (unique index).
- Admin-only for mutations; any authenticated user can see the resulting group as a share target (unchanged).
- Feature is opt-in — off unless `ENTRA_GROUP_SYNC_ENABLED=true`. Local-group behavior is unaffected.
- i18n contract: every new UI string exists in all 16 locales.

## Design

### 1. Graph auth — client credentials, application permissions

- Reuse existing `ENTRA_TENANT_ID` / `ENTRA_CLIENT_ID` / `ENTRA_CLIENT_SECRET` env vars.
- Acquire an app-only token from `https://login.microsoftonline.com/{tenant}/oauth2/v2.0/token` with `grant_type=client_credentials` and `scope=https://graph.microsoft.com/.default`.
- Least-privilege permission on the Entra app registration: **`GroupMember.Read.All` (Application)** — allows listing groups (for the picker) and reading their members. Requires admin consent.
- In-memory token cache with `expires_in - 60s` safety window.

### 2. Data model — no schema change

Reuse the fields reserved in migration 28:
- `user_group.source = 'entra'` for linked groups (existing values otherwise `'local'`).
- `user_group.entra_group_oid` — unique across the table.
- `user_group_member` rows join by `user_id` referencing `user`; the join key with Entra is `user.entra_oid`.

### 3. API surface (all admin-gated except where noted)

| Endpoint | Purpose |
|---|---|
| `GET  /api/groups/entra/search?q=…` | Typeahead against Graph `/v1.0/groups?$search`, top 25. Returns `[{entra_group_oid, display_name, description}]`. Admin. |
| `POST /api/groups/entra/link` | Body `{entra_group_oid}`. Idempotent upsert of `user_group{source='entra'}`; kicks a one-off sync for that group. Returns `{id, name, entra_group_oid, member_count}`. Admin. |
| `POST /api/groups/entra/sync` | Kicks a full sync of every `source='entra'` group. Returns `{command_id}`. Admin. |
| Existing `PATCH /api/groups/{id}` | Refuses (409 "managed by Entra sync") when `source='entra'`. |
| Existing `POST/DELETE /api/groups/{id}/members` | Refuses (409) when the parent group is `source='entra'`. |
| Existing `DELETE /api/groups/{id}` | Unchanged — unlinks the group entirely (cascades to `resource_grant` and `user_group_member` as today). |

### 4. Sync command

- New `commands/entra_group_sync.py`, decorated with `@command`.
- Signature: `SyncEntraGroupsInput { group_id: Optional[str] }`. When `group_id` is provided, sync only that one group; otherwise walk all `source='entra'` groups.
- Per group:
  1. `GET /v1.0/groups/{oid}?$select=id,displayName,description` — refresh name/description snapshot.
  2. `GET /v1.0/groups/{oid}/members?$select=id,mail,userPrincipalName&$top=999` — walk `@odata.nextLink` paging.
  3. Map Entra `id` → local `user.id` via `SELECT id FROM user WHERE entra_oid IN $oids`.
  4. Diff against `SELECT user_id FROM user_group_member WHERE group_id = $gid`.
  5. Insert missing links; delete stale links; **skip Entra members with no local `user` row** (they auto-attach at first login).
  6. Log a one-line summary: `entra_group_sync gid={gid} added={N} removed={M} skipped_unknown={K}`.
- Error handling: 401 from Graph → invalidate token and retry once; 403 → raise `ConfigurationError` (permanent, no retry — matches `stop_on`); 429 → honor `Retry-After` header, defer to surreal-commands retry with exponential jitter.

### 5. Periodic trigger

- In `api/main.py` `lifespan()`, when `ENTRA_GROUP_SYNC_ENABLED=true`, start a single `asyncio.create_task` that sleeps `ENTRA_GROUP_SYNC_INTERVAL_MINUTES` (default 15) and calls `submit_command("commands.entra_group_sync.sync_entra_groups", SyncEntraGroupsInput())`.
- The task is cancelled cleanly on shutdown.
- Manual trigger uses the same `submit_command` path (via `POST /api/groups/entra/sync`).

### 6. Frontend

- `frontend/src/app/(dashboard)/settings/groups/page.tsx` — add a **Link Entra group** button beside **New group**; the sync button is admin-only and shows a spinner while a command is in flight.
- New dialog `LinkEntraGroupDialog.tsx` — debounced typeahead, list Graph search results, single-select, submit.
- Row treatment: when `group.source === 'entra'`, show a "Synced from Entra" badge; hide the add/remove-member controls; disable name/description editing.
- New hooks in `frontend/src/lib/hooks/use-sharing.ts`: `useEntraGroupSearch(query)`, `useLinkEntraGroup()`, `useSyncEntraGroups()`.
- i18n keys: `groups.linkEntra`, `groups.syncEntra`, `groups.syncedFromEntra`, `groups.linkedFromEntra`, `groups.searchEntraGroups`, `groups.searchEntraPlaceholder`, `groups.noEntraResults`, `groups.syncManaged`, `groups.syncStarted`, `groups.syncFailed`, plus `apiErrors.entraGroupManaged`. All 16 locales updated in the same PR.

### 7. Config

New env vars:

| Var | Default | Purpose |
|---|---|---|
| `ENTRA_GROUP_SYNC_ENABLED` | `false` | Master switch — must be `true`/`1`/`yes` for any Entra group sync code to run. |
| `ENTRA_GROUP_SYNC_INTERVAL_MINUTES` | `15` | Periodic loop cadence. Values `< 1` are clamped to 1. |

Reuses `ENTRA_TENANT_ID` / `ENTRA_CLIENT_ID` / `ENTRA_CLIENT_SECRET`.

### 8. Docs

- `docs/SHARING.md` — flip the WBS 4.20 row from "Pending" → "Shipped in PR #N"; note direct-members-only + JIT-attach-on-first-login limitations.

### 9. Security notes

- Client secret stays in env; never returned by any endpoint.
- The Graph search endpoint requires the `ConsistencyLevel: eventual` header (Microsoft Graph requirement for `$search`).
- All new mutating routes go through the existing `require_admin` + CSRF middleware.
- Logging never includes emails from Graph responses; only counts.

Frontend (vitest):
- Dialog opens and closes, debounced search, disabled submit until selection, mutation invalidates the groups list, sync button disables during in-flight command.
- 16-locale parity + placeholder tests unchanged (auto-cover the new keys).

Config:
- `ENTRA_GROUP_SYNC_ENABLED=false` (default) → no lifespan task, no new routes register work performed, existing groups behavior unchanged (regression guard).

## Rollback

- Feature is opt-in via env — set `ENTRA_GROUP_SYNC_ENABLED=false` to disable at runtime.
- Data can be reverted: `DELETE user_group WHERE source='entra'` cascades to `user_group_member` and `resource_grant` (existing `delete_group` route).
