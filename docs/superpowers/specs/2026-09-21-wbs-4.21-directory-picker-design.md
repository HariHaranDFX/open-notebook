# WBS 4.21 — Full Microsoft Graph org directory user picker + JIT-stub Entra group members

**Status:** Approved 2026-09-21
**Branch:** `feat/wbs-4.21-directory-picker`
**Depends on:** WBS 4.19 (WP2b sharing), WBS 4.20 (Entra group sync)

## Motivation

WBS 4.20 shipped Entra group sync but deliberately deferred two loose ends:

1. **Owners and admins can only share with users who have already signed in.** The share dialog and Groups page pickers call `GET /api/users`, which returns JIT-provisioned DB rows only. A colleague who has never opened the app is invisible.
2. **The sync command skips Entra group members with no local user row** and counts them in `members_skipped_unknown`. Those users only appear after they log in — which they cannot do if the resource that would make them log in was never shared with them.

Both stem from the same missing capability: reading the Entra tenant directory via Graph and stubbing local user rows before first login.

## Scope

- Extend the app-only Graph client with tenant user search + single-user lookup.
- Add a tenant directory typeahead endpoint for the picker.
- Add a forgery-validated JIT-stub endpoint that returns the local user id.
- Update `sync_entra_groups` to stub previously-skipped members.
- Reuse the pattern in the share dialog and the Groups admin page via a shared frontend combobox.
- Surface "never signed in" on stub users so admins understand the state.

**Explicitly out of scope** (covered by WBS 4.22): public/anyone-with-link sharing, editor reshare, ownership transfer.

## Backend design

### `api/graph_client.py`

Add:

- `search_users(q: str, limit: int = 25) -> list[{entra_oid, email, display_name}]`
  - Endpoint: `GET /users?$search="displayName:{q}" OR "mail:{q}"` with `ConsistencyLevel: eventual`.
  - `$select=id,mail,userPrincipalName,displayName`. Falls back to `userPrincipalName` when `mail` is null (guest accounts commonly do this).
- `get_user(entra_oid: str) -> {entra_oid, email, display_name}` — single-user fetch, used to validate a submitted OID before stubbing.
- `list_users_by_oids(oids: list[str]) -> list[{entra_oid, email, display_name}]` — chunked `GET /users?$filter=id in ('a','b',...)` for the sync path (chunks of 15 to stay under Graph's URL limit).

All three raise `GraphAPIError` on non-2xx; `_graph_http_exception` in the router already turns 401/403 into a helpful 502.

**Graph permission**: `User.Read.All` (Application) with admin consent, granted alongside 4.20's `GroupMember.Read.All`. Documented in `docs/AUTH.md`.

### `api/routers/groups.py`

Add two routes:

- `GET /api/users/directory?q=…` — signed-in users. Empty q → []. Trims to first 25 hits. Same 502 error mapping as `/groups/entra/search`.
- `POST /api/users/from-entra` — signed-in users. Body `{entra_oid}`. Steps:
  1. Look up existing `user` by `entra_oid` — if found, return it.
  2. Look up by email (needs Graph fetch first to know email) — if found and it lacks `entra_oid`, patch it and return.
  3. Otherwise call `graph_client.get_user(entra_oid)` and insert a stub `user` row with `role='user'` and the deployment `client_id`. Return the local `UserPickerItem`.

Authenticated (not admin-only) because 4.21's product goal is "owners can share with any tenant colleague." Forgery is prevented by validating the OID against Graph before insert — a client can't stub arbitrary emails.

Also extend `GET /api/users` and `GET /api/groups/{id}/members` responses to include a `pending: bool` field derived from `NOT EXISTS(SELECT * FROM auth_session WHERE user = $user.id)`. This drives the "never signed in" badge in the UI.

### `commands/entra_group_sync.py`

Inside `_reconcile_members`, when Entra returns OIDs not in the local `user` table:

1. Fetch their profiles via `list_users_by_oids` (chunks of 15).
2. For each successful profile, insert a stub `user` row and include its id in `desired_user_ids`.
3. Anything still missing after the Graph fetch (deleted account, permission revoked) is counted in `members_skipped_unknown` — but the counter should now be non-zero only in genuine error cases.

Return additions: `members_stubbed` counter alongside the existing three. Log as `stubbed=N` (counts only, per SHARING.md's no-emails rule).

### `api/auth/entra.py`

`_upsert_user()` already searches `WHERE entra_oid = $entra_oid OR email = $email`, constructs a `User` with the existing id, and calls `save()`. That already collapses stubs into the real login row — but there is no test for it. Add one regression test to lock the behavior so a refactor cannot silently regress it. **No code change expected here.**

## Frontend design

### API + hooks

- `sharing.ts`:
  - `searchDirectoryUsers(q)` → `GET /api/users/directory`
  - `stubEntraUser({entra_oid})` → `POST /api/users/from-entra`
  - Extend `UserPickerItem` and `GroupMemberResponse` types with `pending?: boolean`.
- `use-sharing.ts`:
  - `useDirectoryUserSearch(q)` — debounced pattern lifted from `useEntraGroupSearch`.
  - `useStubEntraUser()` — mutation, invalidates `users` and `groupMembers` keys.

### Shared component

`frontend/src/components/sharing/DirectoryUserCombobox.tsx`:

- Combobox showing local users at the top matching the typed text.
- A "Search directory…" affordance appears when the tenant is Entra-configured (surfaced via a small `useIsEntraTenant()` derivable from `useAuth()` — provider is already exposed as part of the auth store).
- When toggled, debounced Graph typeahead runs. Selecting a directory hit calls `useStubEntraUser` → the returned local id is bubbled to the caller's `onSelect(userId)` handler.
- Local hits that already exist as stubs are marked with a small "Never signed in" chip.

The Groups page member-add row and ShareSheet's user picker both use this component. That removes ~40 lines of duplicated `<Select>` code and single-source-of-truths the "never signed in" badge.

### i18n

New keys under `groups` and `sharing`, added to en-US and mirrored to all 15 other locales:

- `groups.searchDirectory`
- `groups.searchDirectoryPlaceholder`
- `groups.searchDirectoryHint`
- `groups.neverSignedIn`
- `sharing.searchDirectory`
- `sharing.neverSignedIn`
- `sharing.addingFromDirectory`
- `apiErrors.entraDirectoryError`

The parity test (`src/lib/locales/index.test.ts`) fails if any locale is missing a key.

## Explicit assumptions (Karpathy)

1. Graph `/users` with `User.Read.All` returns `id/mail/userPrincipalName/displayName` for tenant members. Standard Entra behavior.
2. `User.save()` correctly updates when constructed with an existing id — regression-locked here.
3. Single-tenant Model A deployment (per `docs/TENANCY.md`) — no multi-tenant scoping needed.
